Engineering Methodology: How Local LLM VRAM & Token Speed Are Calculated

Deploying Large Language Models (LLMs) locally requires balancing three competing memory consumers inside GPU Video RAM (VRAM) or Apple Silicon Unified Memory: static model weights, the dynamic Key-Value (KV) attention cache, and framework runtime buffers. Relying on naive rules such as "1 billion parameters equals 1 GB" frequently leads to out-of-memory (OOM) crashes once long context windows are enabled.

1. Static Model Weights Footprint

Model weights represent the frozen neural network parameters stored on disk (typically in GGUF, EXL2, or SafeTensors format) and loaded directly into GPU memory. While unquantized FP16/BF16 weights require 2.0 bytes per parameter, modern 4-bit block quantization methods such as Q4_K_M compress weights to approximately 0.62 bytes per parameter while preserving over 98% of baseline reasoning accuracy.

Weights_VRAM (GB) = Total_Parameters (B) × Bytes_Per_Parameter

2. Dynamic KV Cache & Context Scaling

During autoregressive inference, transformer models cache Key and Value projection vectors for every token in the active context window to avoid recomputing past attention states. As context length scales from 8K to 128K tokens, KV cache memory expands linearly and can exceed the size of the model weights themselves. Enabling FP8 or Q8_0 KV cache quantization cuts this memory overhead in half.

KV_Cache (GB) ≈ 0.00052 × Context_Tokens × (Parameters / 8)^0.65 × KV_Precision_Factor

3. Memory-Bandwidth Bound Token Generation Speed

Single-batch LLM text generation is strictly memory-bandwidth bound rather than compute-bound. For every generated token, the GPU must read all active model weights from VRAM into compute cores. In Mixture-of-Experts (MoE) architectures like DeepSeek-V3, all 671B parameters must reside in memory, but only 37B active parameters are read per token—enabling high token throughput relative to total model size.

Est_Tokens_Per_Sec ≈ (GPU_Memory_Bandwidth_GBs / Active_Weights_GB) × 0.72_Efficiency_Factor
